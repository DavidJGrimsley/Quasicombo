# Radical Mike customization handoff

This is the implementation brief for a future player-facing customization menu. The current build supplies session-only color state and console previews; it does not yet have a menu or saved appearance. Keep the imported Radical Mike and FX Variety Pack assets intact. Use dynamic material instances and project-owned effect copies for runtime changes.

## Shipped assets and material controls

The player skeletal mesh is `/Game/RadicalMike/Mesh/SKM_MegaMikeZ` with body slot `MikeyZ` and lens slot `glass`. The right-hand cannon is a separate `/Game/RadicalMike/Mesh/SM_RadicalBuster` attached at `Buster_RSocket`. The PowerPod mesh `/Game/RadicalMike/Mesh/SM_PowerPod` and its variants are in the pack, but the current player setup does not attach a PowerPod.

| Part | Folder | Shipped choices |
| --- | --- | --- |
| Body | `/Game/RadicalMike/Materials/Body` | `MI_ZMike_Classic`, `Dark`, `default`, `Gray`, `Inferno`, `Mars`, `Oni`, `Oxidized`, `P2`, `P3`, `P4`, `Pluto`, `Prismatic`, `Radioactive`, `RGB`, `Toxic`, `Transcendant` (all prefixed `MI_ZMike_`) |
| Buster | `/Game/RadicalMike/Materials/Buster` | `MI_RBuster_Default`, `Gray`, `Incomprehensible`, `Infinity`, `Inheritor`, `Olive`, `RGB`, `Winnower` |
| PowerPod | `/Game/RadicalMike/Materials/PowerPod` | `MI_PPOD_Default`, `Delivery`, `Experiment`, `Gardener`, `Gray`, `Red`, `RGB` |
| Lens | `/Game/RadicalMike/Materials/Lens` | `MI_ZMike_Lens_Blue`, `MI_ZMike_Lens_Red`; base `M_Glass_parent` |

The body and Buster instances expose three painted mask vector parameters, **`Color R`**, **`Color G`**, and **`Color B`**, plus **`EmissiveColorPicker`**. These names refer to mask regions, not to the red, green, and blue components of one color. Their values are linear RGB colors. The default body instance (`MI_ZMike_default`) uses `Color R = (0.432292, 0.410924, 0.358988)`, `Color G = (0.174911, 0.367115, 1)`, and `Color B = (0.807292, 0.735815, 0.735815)`. Its emissive picker is white. Individual presets can carry additional texture/scalar choices, so a preset switch should change the source material instance and then reapply any explicit color overrides. The lens instances should be offered as their own preset choice; inspect their material controls before assuming the body mask parameters apply to glass.

The source `/Game/FXVarietyPack/Particles/P_ky_thunderBall` has `core`, `spark`, and `sparkTrail` emitters. Its green emitter header in Cascade is an editor organization color, not a runtime tint. The source core is magenta and the sparks are yellow. The source hit effect is `/Game/FXVarietyPack/Particles/P_ky_ThunderBallHit`; it also supplies the shortened muzzle flash because the pack has no separate Thunder Ball firing effect. The game uses copies in `/Game/Quasicombo/Buster/VFX/P_BusterThunderTravel`, `P_BusterThunderImpact`, and `P_BusterThunderMuzzle`. The inner particle core and blast center read `BusterCoreColor` from Mike's light color (currently yellow). The outer electrical layers, trails, and impact shockwave read `BusterSparkColor` from his body-derived color (currently pink). The projectile uses the supplied Thunder particles without an added solid sphere. The copies neutralize the source hues while retaining the original brightness envelopes. Travel uses the dedicated `M_BusterThunderTravel` master with AlphaComposite core coverage following the glow mask and additive electricity; source HDR curves supply brightness. Its floating-point tints normalize hue and compensate luminance without changing Mike's paint. `Project/AuthorBusterThunderTravel.py` rebuilds only travel and its three materials; add `-BusterTravelMaterialOnly` to save just the master when testing core opacity. The approved muzzle/impact keep their shared materials and color handling. The older `AuthorBusterThunderMaterials.py` authors those explosion materials and must not be used for travel-only changes. Imported assets remain intact.

## Runtime model already available

`UQuasicomboLoadoutSubsystem` is the session appearance source. `SetMikeLightColor` and `GetMikeLightColor` update the project-owned body and Buster emissive tint, the lens emissive parameter, Mike's trail, and the Thunder inner core. `SetMikeBodyColor` provides one simple body swatch while retaining three different mask values: `Color R = swatch × 0.55`, `Color G = swatch`, `Color B = swatch × 1.6`, with components clamped to 0–1. `SetMikeBodyRegionColor` and `GetMikeBodyRegionColor` offer independent advanced edits via `EMikeBodyRegion::ColorR`, `ColorG`, and `ColorB`. `OnMikeLightColorChanged` and `OnMikeBodyPaletteChanged` update the current Mike/cannon dynamic materials and active projectiles. The Thunder outer electricity uses `Color G` as its body tint, with a brightness floor for effect visibility. The current yellow-light/pink-body trial uses a custom body palette from session start.

The pickup's selectable Tsunami and Galactic Field aura copies use the same session colors: the main water/field material follows Mike's light color, while smoke, splash, and stars follow the body-derived spark color. The source MegaMagic systems remain intact. Project-owned Niagara systems and tintable material copies live under `/Game/Quasicombo/Buster/VFX`; Galactic Field's main field, particles, and stars now have a final tint input. During the pickup, the selected aura is grounded and stretches upward under Mike while he and the cannon rise together; it ends as the equip animation begins. In PIE, press **7** for Tsunami, **8** for Galactic Field, or **9** for both at once; `Quasicombo.BusterPreview acquire tsunami|galactic|both` offers the same choices through the console during Play. These replay the acquisition for comparison without changing run outcome. For a future menu, reuse the existing light and body APIs; no separate aura color pickers are needed.

PIE console checks: `Quasicombo.BusterColor blue` or `Quasicombo.BusterColor 0.05 0.9 1`; `Quasicombo.BodyColor 0.9 0.1 0.3`; `Quasicombo.BodyRegionColor G 0.2 1 0.1`. Numeric components are linear 0–1. The current implementation applies painted colors to the body and attached Buster mesh; it does not attach or recolor the unused PowerPod. The menu should use the loadout APIs rather than writing to a projectile or mesh directly.

## Menu design to build

Show Mike live in a rotating preview with the cannon equipped, a small muzzle/flight/impact sample, and the selected lens. The first tab should expose **Body color** as one picker, **Light color** as another, and body, Buster, and lens preset selectors. Add an **Advanced colors** disclosure with three separate pickers labeled by the visible body regions they affect, while retaining the material parameter names `Color R/G/B` in developer help. The simple body picker can set all three regions together; editing one advanced region should not unexpectedly move the others. Include a reset action that restores the selected preset's authored mask and emissive values.

Offer every shipped body, Buster, and lens material instance as a preset, with thumbnails captured under consistent lighting. Offer the PowerPod variants only after the pod is attached and its lifecycle is defined. Preset selection should preserve a chosen light color and explicitly edited body colors, unless the player chooses **Reset to preset colors**. Store a preset asset identifier separately from optional color overrides. Avoid copying the default preset's numeric mask values onto a newly selected preset when no override exists. `MI_ZMike_RGB`, `MI_RBuster_RGB`, and `MI_PPOD_RGB` are useful starting points for free color editing, but verify mask response on each variant before deciding which ones allow all three controls.

For persistence, add a versioned `USaveGame` record containing body/Buster/lens preset soft paths, optional PowerPod preset, optional whole-body swatch or three region overrides, and optional light color. Validate asset paths against an allowlist of shipped instances when loading; fall back to defaults if a preset was removed. Apply the stored preset to the mesh first, rebuild dynamic instances, then apply the override colors and broadcast the session state. Keep the current session-only subsystem API as the live interface so firing VFX and lights update at once. Controller navigation, color-blind labeling, and preview visibility against both bright and dark backgrounds should be part of the menu acceptance pass.

## Visual acceptance checks

In `Lvl_Main` PIE, try blue light with red body, then red light with blue body. The traveling inner core, muzzle center, and impact center should follow the light picker; their outer electrical layers should follow body `Color G` without retaining source magenta/yellow or producing black flashes. Fire while standing, running, airborne, and rapidly tapping; each orb should remain at the barrel height. Compare the live character with the menu preview under the same material preset. Check the three mask pickers individually and confirm the cannon shell follows them. Test a near-black body swatch to see whether the spark visibility floor is sufficient without misrepresenting the chosen paint.
